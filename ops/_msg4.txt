fix(evolution): equivalence compares behaviour, not serialised model bytes

问题：shadow 对每个工件做 artifact_digest 比较，包括 model.joblib。
joblib 编码不是字节确定的（dict 顺序、buffer 对齐、memo id），
所以两个预测完全相同的模型仍会得到不同摘要。后果是
preflight:ml.train 这种「不改变输出、只让失败更早暴露」的候选
在字节级判据下永远不可能通过 —— 这一类自我改进被结构性误杀。

实测（2026-11-09）：p7b_4_drd2 的 11 个 ml.train 步全部预测一致，
却因 3 处 model.joblib: digest differs 判 fail。

改法：模型二进制视为派生工件（与已排除的 artifact_manifest.json 同理），
不计入等价分母；但加了非空洞守卫 —— 若某个步只产出模型二进制，
该步记为「unverifiable」（1 total / 0 equal），不允许空比较通过。
报告新增 model_binaries_skipped 字段，避免把跳过量误读为覆盖率。

改后同一候选：equivalence 0.8788 -> 1.0，11/11 步 exit 0，无 mismatch。
门禁随之变为：equivalence pass / success pass / cost n/a / failure fail。

新发现的第二处结构性问题（未改，留待决策）：
failure 门禁要求 failures_in_replay=0，即候选必须让失败消失。
但 preflight 类候选的语义是「更早、更清楚地失败」，不消除失败本身，
所以这类候选在 failure 门禁下仍然过不了。
可推广的候选应是带 cost/quality 主张的（如 throughput:ml.train，
其 acceptance 为 equivalence 1.0 / max_time_ratio 1.2 / min_speedup 1.3）。

另：safety 门禁需要 ops/canary_check.py 的 canary 报告，当前为 manual。

重要约束：任何晋升都不能在 M/A/W 运行期间落地 —— 那会让四臂跑在不同
harness 版本上。R′ 臂必须在 W 结束、晋升落地之后再跑。
