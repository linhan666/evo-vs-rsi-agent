fix(locked)+wip(automl): let locked eval rebuild any representation; measure FLAML

1) evaluation.locked 只接受 --desc-set v1|v2，并把 --radius 2 / --n-bits 2048 写死。
   于是 r1 / b4096 / r3b4096 三种表示在锁定评测时无法重建：predict 要么因宽度不符失败，
   要么在错误的矩阵上成功。这是 p7 里大量锁定评测缺失/不匹配的一个根因。
   现在 radius 与位宽可传（默认 2/2048，旧调用行为不变），且写进收据文件名，
   两种表示不会互相覆盖指标。

2) FLAML 基线（用户选定）的实测结论，单靶点 D2、v1 特征、平衡样本权重：

   算法族      单试验耗时   val AUROC
   lrl1          60.4s      0.6868
   lgbm         252.8s      0.6758
   xgboost       17.0s      0.6758
   catboost      26.4s      0.9307
   rf             0.1s       AttributeError: 'RandomForestEstimator' object has no attribute '_t1'
   extra_tree     0.0s       AttributeError: 'ExtraTreesEstimator' object has no attribute '_t1'

   对照：sklearn logreg 0.9383、rf 0.9133 —— 数据管线正确，问题在 FLAML 侧。

   三个阻塞点：
   a. rf / extra_tree 在 FLAML 2.8.0 下直接抛 _t1 AttributeError（已知类缺陷）
   b. lgbm 单试验 253s，5 表示 x 多试验时单靶点就超时
   c. 低试验预算下 FLAML 的默认首配置很弱（0.68），而 catboost 默认配置 0.93

   等用户确定如何取舍（是否剔除 rf/extra_tree、是否放宽时间预算、表示数是否缩减）。
