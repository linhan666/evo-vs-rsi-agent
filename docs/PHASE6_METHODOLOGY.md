# PHASE6_METHODOLOGY — 这类工作怎么做实验（调研 2026-11）

> 结论先行：**我们跑通了流水线，但还没做「这类论文的实验」。** 差距不在工程，在实验设计。
> 本文列出可复用的实验范式，并据此重新设计 Phase 6 的变体任务。

## 1. 直接相关的两篇工作

### 1.1 RHI：Recursive Harness Self-Improvement（arXiv 2607.15524）

把 harness 定义为**提示层对象**（roles / instructions / contracts / hops），不改可执行代码；用**轨迹内自比对**（当前 harness vs 直接前驱）做迭代，而不是种群搜索。

| 设计 | 与我们的对照 |
|---|---|
| 30 个开放式 ML 研究任务（量化金融 / 机器人 / 制药） | 我们 3 个靶点 × 3 重复 = 9 个**同构**任务 |
| 配对 LLM-as-judge 胜率 | 我们用 AUROC（确定性、更硬） |
| 消融：输出 token 恒定而性能升、缓存与成本下降 | **我们没做这项** |
| 核心论点：收益来自「任务相关的上下文管理」，不是更长输出 | 可直接借用为解释框架 |

**可借鉴**：把「收益」拆成「更少的冗余调用 / 更准的信息流」，而不是只报分数。

### 1.2 Beneath the Surface: What We Overlook When We Talk About Agent Evolution（arXiv 2611.07624，2026-11-05）

**这篇几乎是为我们写的**。它问的正是「benchmark 分数上升 = 真的进步吗」：

- **16 个进化后的 agent 全部**在新任务上得分上升，**同时在原本会做的任务上丢分**；
- 一个案例可靠性 +5.2，却**丢了 10 个原本覆盖的任务**；
- 大多数可靠性提升**伴随部署成本上升**；
- **分数最高的 agent 在四个池子上都不是平均提升最大的**；
- 更严的准入会**丢掉有用的备选**。

它提出的三个研究问题，直接可以当我们的实验骨架：

| RQ | 含义 | 对我们的要求 |
|---|---|---|
| **RQ1 现象学** | 改进是可靠、划算的，还是有覆盖权衡与隐藏成本？ | 报告**覆盖增减**（新解决 / 新丢失）与**每次提升的成本** |
| **RQ2 泛化** | 进化期得来的收益，换到没参与进化的任务还在吗？ | 必须有**留出任务**（held-out），不能只跑引导进化的任务 |
| **RQ3 机制** | 哪类算子真正产生并保住收益？ | 消融：select / analyze / mutate / gate 分别贡献多少 |

它最后给出的方法 **EvoAudit** 正是把这四个环节重做一遍——与我们的「提案→影子→门禁→记账」同构。

### 1.3 Trustworthy RSI 综述（paperz a42867eb）

方法学要求，逐条对我们有用：

1. **固定参照 + 受保护的验收组件**（我们有：锁定评测器 + 不许改标签/划分）✅
2. **资源核算必须含改进器自身的成本**（我们缺：propose/record 的 LLM 调用没算进各组成本）
3. **同一起点、等量资源、统一评测**比较「改过 vs 未改」
4. **任务顺序会影响进展**（我们固定顺序，未做随机化）
5. **初始收益会反转**（需要重复实验）

## 2. 药物筛选 Agent 的实验范式

### 2.1 DO Challenge / Deep Thought（虚拟筛选）

- 固定数据集（100 万构象），**top-1000 重叠率**作唯一指标；
- **限时（10h）与不限时两套设置**——限时下 agent ≈ 人类专家，不限时下人类大幅领先；
- 与**人类团队**直接对比，而不只是与其它 agent 比；
- 消融：不同 LLM 担任不同 agent 角色。

**可借鉴**：给出**预算上限**（token / 墙钟），并在预算内比较；否则 Agent 组的「自主性」没有代价约束。

### 2.2 MolClaw / MolBench（最接近我们的场景）

三级评测：

| 层 | 考什么 | 工具调用规模 |
|---|---|---|
| MolBench-MS | 分子筛选：按约束过滤、按活性排序 | 短 |
| MolBench-MO | 分子优化：改结构保骨架 | 中 |
| MolBench-E2E | 端到端：多阶段、**8–50+ 次工具调用**、多轮反馈 | 长 |

基线选择是关键：**前沿 LLM 直答**、**领域 agent（Biomni）**、**裸 agent 框架（OpenClaw / Claude Code）**三层。

**最重要的一条**：消融结论是「**收益来自技能架构，不是底层 LLM**」——这句话必须能被我们复现，否则我们的 RSI 机制没有独立贡献。

### 2.3 DDA（结构式药物设计）

- **有界修复策略**：每个 wrapper 最多修 2 次（对应我们的重试预算）；
- 两层证据分开报：**管线产物指标** + **框架机制消融**，明确说「不能混为同一成功率」；
- **生产模型与消融后端分开报**，避免混淆。

## 3. 由此得出的实验缺口（我们必须补的）

| # | 缺口 | 后果 | 怎么补 |
|---|---|---|---|
| 1 | **任务同构**（3 靶点同模板） | 无覆盖权衡可测，组间必然趋同 | 补带坑变体 + 留出任务 |
| 2 | **无留出任务** | 无法回答 RQ2（泛化） | 变体任务**不得**进入经验库 |
| 3 | **无覆盖增减报告** | 核心现象（新得/旧失）没测 | 每组记「新解决 / 新丢失」计数 |
| 4 | **改进器成本未入账** | R 组看起来不比 M 贵，是假象 | propose/record 的调用计入 R 组成本 |
| 5 | **无预算约束** | Agent 的「自主」没有代价上限 | 每工单设 token/墙钟上限 |
| 6 | **R 组未真正进化** | R 与 M 实际上是同一组 | 让 R 在轮间跑 提案→影子→门禁→记账 |
| 7 | **无统计**（单次） | 结论不可信 | 每格 ≥3 重复 + CI（我们有 3，但任务同构） |
| 8 | **无消融**（机制拆解） | 不知道是哪一环在起作用 | gate/mutate/analyze 分别关掉重跑 |

## 4. 据此重设计的变体任务（Phase 6B）

设计原则（来自 §1.2 的 RQ1–RQ3）：

- **留出**：变体任务不进经验库，避免「进化期看过」；
- **分层**：MS 级（单工具）/ E2E 级（多工具链）；
- **触发真实失败面**：列名、路径、数据不足、输出冲突、下游依赖；
- **含保留任务**：与 Phase 6A 相同的任务做 2 个，用于测「旧技能是否丢失」。

| # | 任务 | 触发的失败面 | 层级 | 期望区分 |
|---|---|---|---|---|
| P1 | 数据集表头是 `canonical_smiles`，但任务里只说「SMILES 列」 | 列名解析 | MS | A 靠试错，M/R 靠记忆 |
| P2 | 给的 split manifest 路径是相对路径（`.artifacts/...`） | 路径解析 | MS | v4 修复后四组都过 → 测**回归** |
| P3 | 数据集只有 40 行，要求出模型 | `NOT_ENOUGH_RELIABLE_DATA` | MS | 测「知难而退」而非硬训 |
| P4 | 先训 MOR 再训 KOR，要求复用特征缓存 | 跨任务复用 | E2E | M/R 应更快、更少调用 |
| P5 | 训练后要求**同时**输出 MOR 与 IC50 两个模型 | 输出命名冲突 | E2E | 测产物管理 |
| P6 | 与 Phase 6A 相同的 MOR 任务（保留任务） | — | E2E | 测**覆盖是否丢失** |
| P7 | 明确给错路径 `nope.csv`，要求「报错可读、不重试」 | 早失败质量 | MS | 测错误信息 vs 重试循环 |
| P8 | 让它自己发现「上次踩过的坑」 | 经验检索 | E2E | 只有 M/R 能做到 |

规模建议：4 组 × 8 变体 × 3 重复 = 96 工单（比 36 大，但每个更短）。
**先跑 P1 + P6 + P8 三个（4 组 × 3 × 3 = 36）**，覆盖「新失败面 / 保留任务 / 记忆」三个轴。

## 5. 论文实验节应当长什么样

按 §1.2 的骨架：

1. **主表**：四组 ×（成功率、覆盖增减、墙钟、LLM 成本、失败步）；
2. **RQ1 现象学**：可靠性提升 vs 成本上升的散点；新得/旧失计数；
3. **RQ2 泛化**：留出任务上的表现 vs 引导任务；
4. **RQ3 机制**：关掉 gate / 关掉 mutate 各自的消融；
5. **消融**：换 LLM（DeepSeek Flash vs 更强模型）证明收益来自 harness 而非模型；
6. **附录**：每工单的 trace、失败类、版本账本、成本账单。

**没有 1–4，这篇论文只是「我们跑通了一个系统」。**
